# Editora technical-terms dictionary.
#
# Programming, web, data, devops and product terms that prose dictionaries
# flag as misspellings. Spell check accepts every word here, in every
# spell-check language, while "Enable technical dictionary" is on in
# Settings > Spell Check.
#
# One lowercase word per line, sorted within its section; blank lines and
# lines starting with '#' are ignored. Matching ignores case ("Config",
# "config").
#
# What not to add:
# - Plurals and possessives. "config" also accepts "configs" and "config's",
#   and "regex" accepts "regexes". No other form is derived, so list "-ed",
#   "-ing" and "-er" forms ("refactored", "refactoring") yourself.
# - Words with a digit, ALL-CAPS words and camelCase: spell check never looks
#   at them ("utf8", "HTTP", "GitHub"). List an acronym only in the lower-case
#   form people write in prose ("json").
# - Hyphenated and dotted forms: they are checked part by part, so add each
#   part ("reverse" and "proxy", not "reverse-proxy").
# - Short words a typo could make ("nat" for "not", "elt" for "let"): an entry
#   hides that typo in every document.
#
# This list is original/curated for Editora; extend it freely.
